> 项目：设备故障咨询 Agent　版本：v1.0.0　记录时间：2026-11-10
> 本文按时间顺序记录"需求 → 方案 → 编码 → 调试 → 测试 → 交付"过程中真实发生的问题，
> 每条均包含：现象 → 定位依据 → 修改 → 验证结果。

## 一、需求拆解与方案决策

| 决策点 | 备选方案 | 最终选择 | 理由 |
|---|---|---|---|
| 客户端形态 | Web 页面 / WinForms / Tkinter | **Tkinter** | Python 标准库自带，零安装、单进程、可直接打包，符合"无需复杂依赖即可启动" |
| 模型调用 | openai SDK / requests / urllib | **urllib** | 避免任何第三方包，`uv sync` 后无需下载依赖 |
| 检索方案 | 向量库 / jieba 分词 / 规则加权 | **规则加权 + 二元组相似度** | 12 条案例规模下，向量库属于过度设计；纯标准库即可达到可解释的排序结果 |
| 无密钥时的行为 | 直接报错 / 返回固定文本 / 规则兜底 | **规则兜底 + 显式标注模式** | 课堂上没有密钥也必须能演示完整闭环，但不能把固定文本伪装成模型输出 |

**安全边界确认**：只读 `data/fault_cases.json`；不引入 `socket` 对设备的连接；
不生成任何设备控制指令。`llm.py` 是唯一的外网出口，且可被"强制离线"开关关闭。

## 二、编码阶段的真实问题

### 问题 1：Agent 模块导入即报语法错误

- **现象**：`python app.py --list` 抛出 `SyntaxError: invalid syntax`，定位到 `tools.py` 的
  `execute` 方法。
- **原因**：函数签名写成了两行，且第一行末尾漏了冒号：

  ```python
  def execute(self, name: str, arguments: dict | str)
  -> tuple[dict, ToolCallRecord]:
  ```

- **修复**：合并为单行签名。
- **验证**：

  ```
  $ python app.py --list
  知识库：...\data\fault_cases.json
  版本：1.0.0  条数：12
  ```

### 问题 2：工具返回结构不统一，Agent 循环难以消费

- **现象**：初版各工具直接返回字符串或抛异常，模型侧拿不到稳定结构。
- **修复**：统一约定 `{"ok": bool, ...}`；`ToolRegistry.execute()` 内部把
  `ToolError` / `TypeError` / 其他异常统一转成 `{"ok": false, "error": "..."}`，
  并同时产出 `ToolCallRecord`（工具名、参数、耗时、摘要），供界面与日志使用。
- **验证**：`tests/test_tools.py` 覆盖"未知工具""案例不存在""参数非法 JSON""空查询"四种失败路径。

### 问题 3：模型返回空回答导致界面一直等待

- **现象**：在线模式下偶发模型只返回 `tool_calls` 不返回正文，循环结束后无内容可展示。
- **修复**：`_ask_llm` 每轮检查 —— 有 `tool_calls` 继续，有正文返回，
  否则抛 `LLMError("模型返回了空回答")`；外层捕获后自动降级到离线模式，界面不会卡死。
- **验证**：`tests/test_agent.py::TestAgentOnlineFallback` 用不可达地址模拟，确认降级成功且
  回答中仍包含 `EFA-012` 的完整建议。

## 三、界面调试阶段的真实问题

### 问题 4：关闭窗口后 Tk 报 `invalid command name`

- **现象**：测试套件全部通过，但结束时输出

  ```
  invalid command name "2173363156736_drain_queue"
      while executing "2173363156736_drain_queue" ("after" script)
  ```

- **定位**：`_drain_queue` 用 `after(120, ...)` 自循环；`destroy()` 之后该回调仍会触发一次。
- **修复**：保存 `self._poll_id`，重写 `destroy()`：

  ```python
  def destroy(self):
      self._alive = False
      if self._poll_id is not None:
          try: self.after_cancel(self._poll_id)
          except tk.TclError: pass
          self._poll_id = None
      super().destroy()
  ```

- **验证**：`python run_tests.py` 输出不再有噪声，`Ran 30 tests ... OK`。

### 问题 5：界面测试断言 `chat.winfo_width()` 为 1

- **现象**：`test_layout_has_positive_size` 失败，对话区宽度为 1。
- **定位**：`update_idletasks()` 只处理挂起的布局请求，不驱动窗口映射（map）与几何计算。
- **修复**：测试中改为 `update_idletasks()` + `update()`。
- **验证**（实测输出）：

  ```
  窗口: 1180 x 760  mapped=1
  对话区: 589 x 492
  输入框高度: 73
  ```

### 问题 6：默认 `python` 缺少 Tkinter，双击即失败

- **现象**：`python app.py` 报 `ModuleNotFoundError: No module named 'tkinter'`（该解释器为精简版）。
- **定位**：`where python` 命中多个解释器，其中一个不含 tcl/tk。
- **修复**：`start.bat` 遍历 `py -3.15 / py -3.14 / py -3.13 / py -3 / python`，
  用 `-c "import tkinter"` 逐个探测，命中后取同目录 `pythonw.exe` 启动，避免黑框。
- **验证**：双击 `start.bat` 正常弹出窗口；`start.bat selftest` 输出 6 项检查全部 True。

## 四、检索质量调优

初版仅用关键词命中，出现两个问题：

1. **漏召回**：用户说"油缸没劲、压力表上不去"，未命中"压力不足"关键词；
2. **误召回**：查询"报警"命中多条案例，排序不稳定。

改进后的打分（`knowledge.py`）：

```
score = 0.42 * 设备名命中
      + 0.20 * 关键词命中数(上限 4 个)
      + 0.55 * 现象文本 Dice 相似度
      + 0.20 * 全案例文本 Dice 相似度
score = 1 - exp(-1.15 * score)      # 压缩到 0~1，避免线性叠加越界
```

实测：`液压站压力上不去，油缸动作无力` → EFA-001，score = 0.701；
`注塑机模具冷却水路堵塞` → 无命中（低于阈值 0.22），走"缺乏依据"分支。
两个用例已固化为单元测试，防止后续调参回退。
